## Intent

A learning project: an ISO 8583 card switch in plain Java 25 (no frameworks, JUnit only), built by
Mahmoud to learn modern Java and card authorization. Target flow (`scope.md`): a fake terminal
sends an authorization request (0100) → the switch → one fake issuer → the issuer answers with a
0110 carrying DE39 (response code) `00` → the switch sends it back to the terminal on the same
connection.

Current decision: **thin walking skeleton** (2026-11-11): one issuer, no routing, one request in
flight (no STAN/RRN matching), the codec reads only MTI + bitmap. Brief 01 (done 2026-11-14) built
the first leg.

What runs today (commit `b88cdc2`):
- `SimRunner` (terminal sim) connects to `localhost:5001`, frames the 181-character sample with a
  4-digit ASCII length header (`MessageWriter.frame`) and writes it as UTF-8 (`Transporter.writeToStream`).
- `Main` calls `Switch.listen()`, which opens a `ServerSocket` on 5001, prints "waiting...",
  accepts one connection, and reads one framed message (`MessageReader.readMessage`: 4 header bytes,
  then exactly N bytes with `readNBytes`). It returns only the text. `Main` decodes it with
  `Codec.decodeMessage` and prints `MTI: 0100`. Both programs then end.
- Last recorded real run: Brief 01 check-in, 2026-11-14 (pass). Last Maven test run on disk:

Domain reference used: `references/domains/iso8583-switch.md`. In scope today: §1 items 1–3

## Notes on findings not in the next steps

### DESIGN-writer-split
The reader does header + decoding + reading in one method; the writer's half is split across
`MessageWriter.frame` (header, from text) and `Transporter.writeToStream` (UTF-8 encoding, sending). That
split caused DOMAIN-header-counts-chars: `frame` never holds the bytes, so it counted characters.
It also lets anyone call `Transporter.writeToStream(out, message)` and skip the header. Direction: a
`writeMessage(OutputStream, String)` that mirrors `readMessage(InputStream)`; `Transporter` then
shrinks to `connect` (which also hard-codes `"localhost"`). If he changes the shape, the step 1
round-trip test is the safety net. Read: *Clean Code* ch. 17, G22 "Make logical dependencies
physical"; ch. 10 (cohesion).

### ERR-frame-too-long
His decision (2026-11-14): throw if the message is too long for 4 digits. Not built. The concrete
failure: `String.format("%4s", 12345)` gives `"12345"` (the width is a minimum, not a maximum), so
the header is 5 characters; the reader takes `"1234"` as the length and the `"5"` as the first body
byte. `%04d` zero-pads in one step (tip from Brief 01) but grows to 5 digits the same way, so the
check is needed either way, and after step 1 it must check the byte count. Test with
`assertThrows(IllegalArgumentException.class, ...)`. Verified on JDK 25.0.5. Read: *Clean Code*
ch. 7.

### ERR-truncated-frame
`readNBytes(n)` returns fewer than n bytes if the stream ends first, and `readMessage` passes the
short text on as if it were whole (verified: header `0010` followed by `"012"` returns `"012"`).
An empty stream gives `NumberFormatException: For input string: ""`, which doesn't say "the
connection closed". Direction: compare the bytes read with the header and throw an exception that
says what was expected ("expected 10 bytes, got 3"). Later, when the switch loops, tell apart
"closed between messages" (normal end) from "closed mid-message" (an error). Domain reference §4
"Precise errors", §6 "truncated frame". Good candidate for a next review step.

### DESIGN-fixed-de-fields
Still `de2/de11/de37/de41` with getters and setters; a search finds no use outside `Message`.
Parked by the thin skeleton. It will come back when the issuer sim has to build a 0110 with DE39:
adding a `de39` the same way grows the problem. Options for that brief: (a) the issuer copies the
request and changes only the MTI (no DE39, so the terminal can't tell approve from decline), (b) a
hard-coded 0110 in the sim, (c) a minimal encoder (set bit 39, insert the field). That's a brief
design question. Asked "why these four fields" three times without an answer; don't ask a fourth
time, let the 0110 work raise it.

## Design notes

**Recommended (in the report):** `transport` as a mirrored pair, `readMessage(InputStream)` /
`writeMessage(OutputStream, String)`, both counting bytes. `Switch.serve(port)` owns the sockets
in try-with-resources and calls `handle(InputStream fromTerminal, OutputStream toTerminal)`;
`Main` only starts it. `handle` is testable with `ByteArrayInputStream` / `ByteArrayOutputStream`:
no network, no threads.

**Alternative (not recommended), writer:** keep `frame(String) → String`, just count UTF-8 bytes
(step 1's minimal fix), and keep `Transporter.writeToStream`. It works, but the charset is then named in two
classes and the header can still be skipped.

**Alternative (not recommended), where the conversation lives:** `Switch.acceptTerminal()` returns
the `Socket` and `Main` owns it. `Main` would grow into the switch and `switching` would hold no
switching. Brief 01 step 5 also planned the switch to decode.

**For the next brief (the way back):** the switch is a server to the terminal and a client to the
issuer. `handle` will need the issuer's connection too; avoid a four-stream parameter list
(*Clean Code* F1): a small type holding one connection's input and output, or an issuer object
passed in, would do. Decide in the brief's design pass. Ports: a second named constant.

**Strings vs bytes:** strings are fine while every field is ASCII and the bitmap is hex. Most real
networks send a binary bitmap; `new String(bytes, UTF_8)` corrupts bytes ≥ 0x80 that aren't valid
UTF-8. Move to `byte[]` when the first binary field arrives (domain reference §4 "Bytes are
bytes").

**Java 8 → now (left out of the report for length):** in Java 8, `getBytes()` with no charset
used the machine's default (different on Windows and Mac); since Java 18 (JEP 400) it's UTF-8
everywhere. His tests use `getBytes()`, production names UTF-8: consistent on Java 25.

**Package tree and dependencies:** `org.moe` (Main) → `codec`, `switching`; `switching` →
`transport`; `simulator` (SimRunner, Terminal) → `transport`. No cycles. The metrics script's
"zone of pain" flags on `codec` and `transport` are noise at this size (small concrete leaf
packages). `scope.md` says `sims`; the package is `simulator` (harmless).
