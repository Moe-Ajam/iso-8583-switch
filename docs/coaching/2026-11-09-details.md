## Intent

A learning project: an ISO 8583 switch in plain Java 25 (no frameworks). A fake terminal sends an
authorization request (0100); the switch decodes it, routes it to a fake issuer, and relays the
response (0110) back. Components planned per `scope.md`: `codec`, `transport`, `switching`,
`simulator` (terminal, issuer). Today only the codec exists and only reads MTI + primary bitmap.
Domain reference used: `references/domains/iso8583-switch.md`. Tier: parser-only learning project
(items 1–4 of the switch list apply).

Sample check: `SAMPLE` is 181 ASCII chars. Bitmap `723C448108E08000` → fields 2, 3, 4, 7, 11, 12,
13, 14, 18, 22, 25, 32, 37, 41, 42, 43, 49. Bit 1 is 0, so no secondary bitmap. The data after
position 20 matches these fields (DE2 LLVAR "16"+PAN, DE32 LLVAR "06"+"100001", DE49 "682" SAR).
`SAMPLE_WITH_HEADER` carries a 4-digit ASCII length header "0181" (= 181).

## Notes on findings not in the next steps

### DOMAIN-bitmap-decode
The real next domain step: turn 16 hex chars into the set of present field numbers (bit 1 = most
significant bit of the first hex digit). Needs hex → binary and bit numbering, a heavy new concept
for him: give it its own review/lesson. Then parse each field with a cursor (index that advances),
driven by field definitions (fixed vs LLVAR). Golden test: the 17 numbers listed in Intent.

### DESIGN-mutable-bean
Setters let anyone change a decoded message. Once he's met records, a `record Message(String mti,
String bitmap, Map<Integer,String> fields)` with `Map.copyOf` is the natural shape. Not before the
decision above is settled.

### ERR-short-input
Later: check length first and throw an exception that says what was expected ("need 20 chars for
MTI+bitmap, got 12"). Domain reference §4 "Precise errors".

### BUILD-release-flag
`<maven.compiler.release>25</maven.compiler.release>` also checks you only use Java 25's API. One line.

## Design notes

Recommended: static pure `readMessage(String) → Message`; Message holds `Map<Integer,String>`
fields keyed by DE number, plus `field(int)`. Alternative (later, domain ref §4): field definitions
as data (`FieldDefinition` per DE: fixed/LLVAR/LLLVAR, max length) and a cursor over `byte[]`.
Strings are acceptable for now because the sample is all ASCII; move to bytes when binary fields
(DE52, DE55) or BCD interfaces appear.

Package tree: `org.moe` (Main), `org.moe.codec` (Codec, Message), empty `transport`, `switching`,
`simulator.issuer`, `simulator.terminal`. No cycles. Note `scope.md` says `sims` but the package is
`simulator` — harmless, could align the doc.
